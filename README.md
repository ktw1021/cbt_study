# CBT 빈칸 학습 앱

긴 법률·시험 원문을 **빈칸 채우기**로 외우기 위한 웹 앱입니다.  
인터넷 서버에 올리는 방식이 아니라, **지금 쓰는 브라우저(노트북·PC) 안**에 카드와 학습 기록이 저장됩니다.

---

## 처음 쓰는 방법

1. 앱을 브라우저에서 연다 (아래 **실행 방법** 참고).
2. **이름 + 4자리 숫자 비밀번호**로 회원가입하거나, 기존 계정으로 로그인한다.
3. **카드관리**에서 폴더·카드를 보거나, **카드제작**에서 새 카드를 만든다.
4. **학습모드**에서 학습 방식을 고른 뒤 **학습 시작** → 문제를 보면서 해설 빈칸에 답을 넣고 채점한다.

---

## 실행 방법

브라우저 주소창에 `file://`로 HTML 파일만 여는 방식은 동작이 불안정할 수 있다. **로컬 서버**로 여는 것을 권장한다.

```bash
cd cbt_blank_study_app
npm run dev
```

브라우저가 `http://localhost:3000`으로 자동으로 열린다. 파일을 고치면 **자동 새로고침**된다.

---

## 로그인 / 계정

- **회원가입:** 이름 + 4자리 숫자 비밀번호(0000~9999).
- **로그인:** 같은 브라우저에 저장된 계정 목록에서 고른 뒤 비밀번호 입력.
- **계정 전환:** 사이드바 사용자 이름을 누르고 다른 계정의 비밀번호를 입력한다. 취소하면 현재 계정을 유지한다.
- **새로고침**해도 같은 브라우저면 로그인 상태가 유지되는 경우가 많다(세션 저장).
- 계정·카드 데이터는 **이 PC·이 브라우저**에만 있다. 다른 기기·다른 브라우저와는 **자동으로 공유되지 않는다**.
- 옮기려면 사이드바 **전체/유저/폴더 내보내기** JSON 파일을 쓰고, **가져오기**로 불러온다.

## 카드 만들기

카드는 **문제**와 **해설** 두 덩어리로 나뉜다.

| 구분 | 내용 |
|------|------|
| **문제** | 시험에 나올 법조문·지문 등 (빈칸 없음) |
| **해설** | 암기할 문장. 여기만 **빈칸**을 만든다 |

**카드제작** 흐름:

1. 제목·폴더 입력.
2. **문제** 칸에 문제 텍스트 입력.
3. **해설** 칸에 암기 문장 입력 → 외울 단어를 드래그 → **Ctrl+B** (또는 「선택 → 빈칸」).
   해설이 길면 칸 오른쪽 **집중 편집**으로 화면을 크게 쓰고, **닫기** 또는 **Esc**로 돌아온다.
4. (선택) 아래 **「빈칸별 정답」**의 **동의어** 칸에 다르게 써도 정답으로 칠 표현 입력. 여러 개는 `||`로 구분.
5. **저장** (또는 **Ctrl+S**).

### 서식·각주

문제와 해설에서 글자를 선택한 뒤 툴바로 적용한다. 저장 형식은 평문 + 위치 정보이며, 임의의 HTML은 저장하지 않는다.

| 동작 | 단축키 (편집기 포커스) | 마우스 |
|------|------------------------|--------|
| 빈칸 만들기 | **Ctrl+B** (해설만) | 「선택 → 빈칸」 |
| 볼드 | **Ctrl+Shift+B**. 문제 칸에서는 **Ctrl+B** 도 볼드(브라우저 기본 서식은 저장하지 않음) | **B** |
| 글자색 | **Ctrl+M** 다음 물리키 K/B/R/G (`KeyK` 등. 한글 입력 모드에서도 같은 키), 또는 **F2** (마지막 색) | 색 견본+▾ (글자 「글자색」은 안 보임). 표시색은 캐럿/선택 범위의 실제 색(섞이면 검정) |
| 형광펜 | **F3** | **형광** 글자만 노란 배경(버튼 칸은 그대로) |
| 정렬 | **Ctrl+Shift+L/C/R/M** (왼/가/오/양) | 양쪽·왼쪽·가운데·오른쪽 아이콘. **문단**(명시적 줄바꿈) 단위. 기본은 왼쪽. 캐럿이 있는 문단, 또는 선택이 걸친 문단. 같은 버튼을 다시 눌러도 풀리지 않고 그 정렬을 유지. 양쪽정렬은 자동 줄바꿈된 줄만 양끝에 맞추고, 문단의 마지막 줄은 늘리지 않음 |
| 각주 | **Alt+N** | 「각주」 — 그 칸 본문에 캐럿이나 선택 범위가 있을 때만. 없으면 「각주를 넣을 곳을 선택해 주세요.」 |
| 서식 해제 | | 「해제」 — 선택 구간의 볼드·색·형광·정렬만 지움. 각주·메모는 지우지 않음 |

브라우저가 가로채는 키(일부 Ctrl+조합, F2/F3)는 OS/브라우저에 따라 동작하지 않을 수 있다. 툴바 버튼은 항상 있다. **Ctrl+N,N** 은 새 창과 겹쳐 쓰지 않는다.

각주는 선택 구절의 수정 이유·취지다. 카드 전체 **메모**와 다르다. 번호는 **문제·해설 칸마다 본문에 표시되는 위치 순서로** 1, 2, 3…을 매기며, 추가·삭제하면 본문·미리보기·목록이 함께 갱신된다. 패널 제목줄 오른쪽의 **문제/해설** 탭으로 그 칸 각주만 본다. 카드 수정에 들어오면 **해설 + 각주** 탭이 기본이다. 제작 화면 본문 번호를 누르면 해당 각주 목록을 열고 잠깐 강조한다. 목록의 삭제 버튼과 편집기에서 번호에 인접한 Backspace/Delete는 확인 후 즉시 반영되며, 취소하면 그대로 유지된다.

제작·학습이 **같은 각주/메모 패널**을 쓴다(집중 편집에서도 보임). 목록에서 **각주 제목을 누르면 본문 위치로 이동하며 그 번호를 잠깐 강조**하고, **행 오른쪽 화살표**는 그 각주만 접거나 펼친다. 본문은 기본으로 모두 펼치며 목록 위 화살표로 전체를 접거나 펼친다. 미공개 빈칸 답을 자동으로 보여 주지 않는다. 메모는 카드 하나당 하나이며 칸을 나누지 않는다. 학습 본문의 번호에 마우스를 올리면 각주 내용이 뜨고, 클릭하면 해당 각주 탭을 열어 목록 항목을 잠깐 강조한다. 관리 미리보기의 번호는 해당 카드의 각주 내용을 연다.

카드 수정 화면 임시저장 왼쪽 **학습하러 가기**는 저장된 그 카드 한 장으로 학습을 시작한다. 학습 중 **수정**으로 들어온 뒤에는 **이어서 학습하기**로 바뀌고, 진행 중이던 큐·위치·입력·채점을 유지한 채 돌아간다. 저장하지 않은 수정이 있으면 이동 전에 묻는다(초안은 남기고, 자동으로 확정 저장하지 않는다). 아직 저장하지 않은 새 카드는 먼저 저장하라고 안내한다.

학습 중 **본문 크기** 슬라이더는 앱 안에만 적용되고(브라우저 줌과 별개), 빈칸 입력칸 크기는 그대로다.

정답 자체는 **해설에서 빈칸으로 만든 그 단어**가 그대로 쓰인다(읽기 전용). 바꾸려면 해설 본문의 단어를 고친다.
동의어만 따로 덧붙이는 방식이라 본문과 정답이 어긋나지 않는다.

빈칸은 **추천 5개**, **후보 고르기** 등으로 자동 생성할 수도 있다.  
제작 화면 미리보기에서는 빈칸이 `○○○` 모양으로 보인다.

## 카드 관리

- **폴더** 트리로 카드를 분류한다.
- 카드를 드래그해서 다른 폴더로 옮길 수 있다. **Shift+클릭**은 보이는 목록에서 연속 범위 포커스, **Ctrl+클릭**은 카드를 하나씩 추가·해제한다. 포커스된 카드 아무거나 폴더에 놓으면 그 집합만 한꺼번에 이동한다(포커스 밖 카드를 드래그하면 그 한 장만).
- 사이드바 체크박스는 **학습 대상** 선택이다. 카드관리 목록의 포커스와는 별개다.
- 카드 선택·플래그(색)·검색·필터로 학습 대상을 고른다.
- 상세 화면에서 카드 내용을 수정할 수 있다.

## 학습하기

**학습모드** → 방식 선택(전체·폴더(여러 개 가능)·플래그·최근 오답 등) → 미리보기에서 카드 체크 → **학습 시작**.

| 화면 | 역할 |
|------|------|
| **왼쪽** | **문제** (빈칸 없음). **가리기**로 접으면 확보된 폭은 해설로 간다. 각주 칸 폭은 유지 |
| **오른쪽** | **해설** — 문장 안에 빈칸 입력. 스크롤 따로 |
| **해설 위** | 「빈칸」에 마우스를 올리거나 클릭해 목록을 열고 원하는 빈칸으로 이동 |
| **아래** | 채점 결과, **전체 채점** / **다시 풀기** |
| **오른쪽 패널** | 각주 목록 · 카드 메모 (접을 수 있음). 좁은 화면에서는 본문 아래에 둔다 |

- 빈칸에 답 입력 후 **Enter** → 그 빈칸만 채점.
- **전체 채점** → 모든 빈칸 한 번에 채점.
- 빈칸에 **마우스를 올리면 정답**을 볼 수 있다. **채점 전후 모두** 된다. 아직 안 푼 빈칸은 1.5초 게이지가 찬 뒤, **채점이 끝난 빈칸은 0.3초**만에 뜬다. 인정되는 답이 여러 개면 전부 표시된다.
- **유사도** 슬라이더로 오타 허용 정도 조절 (기본 80% 근처).
- **실제 문제 풀 때만** 사이드바가 자동으로 접힌다. 카드 제작·관리에서는 접히지 않는다.
- 학습 중 **새로고침**하거나 카드관리·카드제작으로 나가도 진행을 보존한다. **이어서 학습**으로 카드 목록·순서·입력·채점 상태를 복구한다.

### 회독

- 한 카드의 **빈칸을 모두 정답 처리하면 회독이 자동으로 +1** 되고, 그 자리에 「+1 회독 성공」이 뜬다.
- 틀렸다가 고쳐서 결국 다 맞혀도 **+1**로 인정된다. 다만 **한 번의 시도에서 회독은 최대 1회**만 올라간다.
- **다시 풀기**를 누르면 새 시도가 시작되어 다시 회독을 쌓을 수 있다.
- **회독 +1 / -1** 버튼으로 직접 조절하는 것도 그대로 된다.
- 채점하면 **최근 정답/오답**(`lastResult`)과 **오답 횟수**도 카드에 기록된다. 오답 횟수 역시 시도당 1회만 올라간다.

### 문제를 다 풀면

- 회독 +1 표시가 사라진 뒤 **「다음 문제로 넘어가시겠습니까?」**가 뜬다. **Enter**만 눌러도 「확인」이 선택된다.
- 마지막 문제까지 끝내면 **「홈으로 / 학습모드로 / 취소」**를 고른다. 홈·학습모드를 고르면 저장된 학습 진행은 정리된다.

## 무엇이 저장되고, 무엇은 안 되나

데이터는 브라우저 **IndexedDB**(`cbt_blank_study_v1`)에 저장된다. 같은 기기·같은 브라우저를 지우지 않는 한 유지된다.

| 저장됨 | 저장 안 됨 |
|--------|------------|
| 카드 저장·수정·삭제, 서식(`textMarks`)·각주 | 확정 저장하지 않은 수정(별도 초안으로 보존) |
| 빈칸 입력·채점 결과, 진행 중인 학습 세션 | 되돌리기(Undo) **기록** — 새로고침하면 사라짐 |
| **메모 저장**으로 저장한 카드 메모, 학습 본문 크기 | |
| 회독 ±, 플래그, 폴더 구조 | |
| JSON 내보내기 파일 (백업용) | |

**메모 저장**은 제작·학습 패널의 메모 탭에서 한다. 제작 화면에서는 해당 카드의 메모만 저장하며, 다른 본문 수정은 따로 저장해야 한다.

## 되돌리기 (Undo)

**된다.** 다만 범위를 알고 쓰는 것이 좋다.

- 사이드바 **되돌리기** 또는 **Ctrl+Alt+Z**
- 카드·폴더·채점·메모 저장·가져오기 등 **데이터를 바꾸기 직전** 상태로 최대 **60단계**까지 되돌릴 수 있다.
- **같은 탭을 연 상태**에서만 유효하다. **페이지를 새로고침하거나 닫으면** 되돌리기 목록은 **사라진다**.
- 텍스트 입력 중 **Ctrl+Z**(글자 하나 취소)와는 별개다.

되돌릴 게 없으면 「되돌릴 상태가 없습니다.» 알림이 뜬다.

## 백업

- **전체 내보내기** — 앱 데이터 통째로 JSON
- **유저 내보내기** — 로그인한 사용자 데이터만
- **폴더 내보내기** — 선택 폴더만
- **가져오기** — JSON 파일. 폴더는 내 계정에 추가, 유저·유저들은 새 계정으로 추가(이름 겹치면 `(1)`)

## 기술 메모 (개발용)

```
cbt_blank_study_app/
├── index.html
├── css/          variables, layout, components
├── js/
│   ├── main.js   진입·이벤트
│   ├── core/     store, IndexedDB
│   ├── domain/   카드·빈칸·쿼리
│   ├── services/ undo, 채점, import/export
│   ├── ui/       화면·렌더
│   └── app/      actions.js — 버튼·저장·학습 로직
└── package.json  npm run dev
```

빌드 단계가 없다. `index.html`이 ES 모듈(`js/main.js`)을 직접 읽고, 브라우저가 그대로 실행한다.
`package.json`에는 로컬 서버를 띄우는 `dev` 스크립트 하나뿐이며, 배포는 이 파일들을 GitHub Pages가 그대로 서빙한다.
